✅ 调试完成 — 总结

        
    
          
  • 最终输出：res = [3, 3, 5, 5, 6, 7]，与期望一致。
    • 
          
  • 时间复杂度 O(n)：每个元素最多入队一次、出队一次（被挤或被 poll），虽然内层有 while，但均摊下来每个元素只被处理常数次。
    • 
          
  • 易错点：队列里存的不是整个窗口的内容，而是「可能成为最大值的元素」。例如窗口 [1,3,-1] 时队列只有 [3,-1] —— 1 在 3 入队时就被第 17 行挤掉了。
    • 
          
  • poll 的判断逻辑：窗口左端元素移出时，只有它恰好等于队头（真的是当时的最大值）才需要 deque.poll()；否则它早已被 add 挤出队列，无需处理。
    • 
          
  • add 的挤尾逻辑：新元素入队前挤掉队尾所有比它小的元素 —— 它们比新元素小且更早滑出窗口，不可能再成为任何后续窗口的最大值，这保证了队列单调递减、队头恒为最大值。
